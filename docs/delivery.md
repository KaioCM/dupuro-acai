# Dupuro Delivery (/delivery/)

Parte do contexto do projeto (índice e regras gerais no `CLAUDE.md` da raiz).

- **Dupuro Delivery** (`/delivery/`, projeto iniciado 2026-10-11 — ver memória `dupuro-delivery`): venda de **caixas varejo ≥1L + granola** com entrega própria (o Kayo entrega). Visual v2 (2026-10-11, refeito a pedido do Kayo — "mistura": anúncio com a linguagem candy da home + compra limpa estilo app; fotos reais do Drive da empresa em `assets/img/delivery/`, 1100px q80). Páginas: `delivery/index.html` (anúncio) → `pedido.html` (loja+checkout em 3 TELAS: 1 escolher → 2 entrega [dados+endereço+horário] → 3 revisar e pagar; `irPara(n)` mostra uma `.dl-etapa` por vez, "Continuar" da barra valida e avança, Voltar/back do celular volta via `history.pushState`, indicador de etapas clicável) → `acompanhar.html?t=<token>` (status; mapa ao vivo = Fase 3). JS `delivery/delivery.js` (fetch puro, sem supabase-js; `janelasDisponiveis` = regra manhã/tarde com corte, Cuiabá UTC-4) + `delivery.css`. Banco (migration_036/037): `delivery_config` (linha única jsonb: origem, taxa {base 5, km_base 3, por_km 1.5, max_km 20 (era 15; aumentado pra cobrir Várzea Grande)}, janelas manhã 8–12 corte 7h / tarde 13–17 corte 11h, dias seg–sáb, ids de produtos) — leitura pública, admin edita; `delivery_pedidos` (código DLV-XXXX, token de rastreio, itens jsonb, status aguardando_pagamento→pago→em_rota→entregue | cancelado/expirado) **sem acesso anon**; RPCs públicas `delivery_catalogo()` (estoque pela linha dona/por sabor) e `delivery_rastreio(token)`; `delivery_confirmar_pagamento` (só service_role: marca pago + baixa estoque, idempotente). Edge Functions (verify_jwt false, públicas): **`delivery-cotacao`** (**OpenRouteService** em `api.heigit.org` — trocado do Google, que pedia cartão/pré-pagamento: localiza por Pelias (número exato) → coordenada do CEP (AwesomeAPI, sem chave) → Pelias rua/bairro; rota driving-car → km de carro; nunca aceita lat/lng do cliente; origem = lat/lng fixos na config → taxa arredondada pra cima em R$0,50; devolve cotação **assinada HMAC**, vale 2h), **`delivery-checkout`** (revalida preço/estoque no banco, assinatura da cotação e janela; cria pedido + preferência **Checkout Pro do Mercado Pago**, Pix+cartão sem boleto; expira pendentes >3h), **`delivery-mp-webhook`** (reconsulta o pagamento na API do MP — nunca confia no corpo; aprovado → confirmar_pagamento). Secrets pendentes: `ORS_API_KEY` (conta criada pelo Kayo), `MP_ACCESS_TOKEN`, opcional `MP_WEBHOOK_SECRET`; endereço (pedido do Kayo): no TOPO o botão "Não sabe o endereço certinho? Marque no mapa" (estilo Uber: marca o ponto → reverse geocoding Nominatim/OSM no navegador preenche rua/número/bairro/cidade/CEP, tudo editável, e pede só o que faltar); "ou preencha" com CEP OPCIONAL — se digitado, ViaCEP preenche e TRAVA só o que trouxe (cidade/rua/bairro; CEP de Cuiabá não vira VG); sem CEP ou apagando o CEP, tudo livre; cidade = select Cuiabá/Várzea Grande. **Marcar no mapa**: o botão abre uma gaveta com Leaflet 1.9.4 (cdnjs, carregado sob demanda) + tiles OpenStreetMap — pino fixo no centro, cliente arrasta o mapa ou usa o GPS; o ponto vai como `pin_lat/pin_lng` e o servidor usa ele DIRETO (decisão do Kayo: entrega é exatamente onde marcou, então não há trava de distância), só exige estar na área Cuiabá+VG. Sacola editável (−/+/remover) na seção e numa gaveta aberta pela barra de baixo ("Ver sacola"); o texto montado vai pra cotação (geocoding) e é o que fica salvo no pedido. `delivery/maps-config.js` não é mais usado (autocompletar do Google removido). Falta na Fase 1: aba Delivery no admin (pedidos + config). **Rodada de UX (2026-10-23, critique 27/40):** tela 1 é lista compacta tamanho→sabor (`aberto`, só sabores com estoque; esgotados em texto); aviso "Entrega a partir de R$ X · próxima" (`#freteAviso`); frete calcula sozinho (`agendarCotacao`, sem botão; `cotSeq` descarta resposta velha); erro via `erroNaSecao` (bloco + campo); mapa não sobrescreve endereço digitado (`#mapaSug`); tela 3 com um botão "Pagar R$ X" (barra some); **opt-in do WhatsApp escondido até o número definitivo** (reativar tirando `hidden` do `.dl-aceite`); fotos via `D.miniatura`.
- **Jev escolhe o candidato do endereço (2026-10-23, `delivery-cotacao` v11):** entre os resultados do Pelias, uma pergunta Choice escolhe o que é o mesmo lugar do texto digitado (mesma rua, número, bairro) ou `nenhum` (conf. ≥ 0,7 → descarta todos e cai no CEP/bairro); conf. < 0,5, erro ou sem `TYPESAFE_API_KEY` → ordem do Pelias, como antes. Timeout 3 s. Só o endereço vai ao Jev (nunca nome/telefone). Teste sintético 4/4 (incluindo 3 casos em que o 1º do Pelias estava errado).
